# تقديم ريشة إلى دليل Claude

3 أكتوبر 2026 · مواد إعداد للتقديم، ولم يُقدّم التطبيق أو يُعتمد بعد.

الحزمة: `risha-screenwriting`، والمهارة: `screenplay`. مصدر GitHub المخطط: `https://github.com/5lov1999khalifa/risha-claude-plugin`. الحزمة في جذر المستودع، لا في مجلد فرعي. يشير Marketplace الخاص بريشة استوديو إلى الحزمة نفسها؛ نشره على GitHub لا يساوي الظهور في دليل Anthropic.

## ما يلزم قبل فتح التقديم

- تحقق من تشغيل نسخة التوزيع في Claude Code مع Node.js 22+، ومن بدء `dist/server.mjs` المرفق عبر stdio. اختبر الكتابة، والبناء، والفحص، والتعديل المحدد، وحفظ نسخة جديدة وفتحها في ريشة. لا تعتبر نجاح فحص manifest اختباراً لسلوك المهارة أو الملف.
- انشر المصدر المقصود بعد مراجعة عدم احتوائه أسراراً أو مواد مستخدمين أو ملفات التطبيق الأصلية. يحتاج نشر الدليل مستودع GitHub عاماً، ويمكن بدء التحقق والمراجعة بمستودع خاص وفق متطلبات البوابة.
- احتفظ بملف README كافٍ ورخصة الحزمة وإشعارات تراخيص الاعتماديات. رخصة هذه الإضافة تخص كودها الجديد ولا تمنح حقوقاً في برنامج ريشة الأصلي.
- خادم الإضافة Node محلي. مهارتها تدعم المحادثة الإرشادية، لكن أدوات stdio لا تعمل داخل محادثة Claude على الويب أو الجوال. لا تعرض الإضافة كاتصال سحابي مكتمل.

حجم الحزمة والملفات المقروءة يؤثران في المراجعة. الملف النصي غير الصوري الذي يتجاوز 256 KiB قد يحتاج مراجعة بشرية؛ قد يتجاوز ملف الخادم الذي يجمع الاعتماديات هذا الحد. لا تُخفِه بالتمويه أو التصغير لإيهام الفحص؛ احتفظ بمصدر مقروء وتعامل مع نتيجة البوابة الفعلية. راجع [قائمة متطلبات التقديم](https://claude.com/docs/plugins/pre-submission-checklist).

## مسار التقديم الرسمي

1. استعمل الجهة التي ستملك الإضافة على المدى الطويل. يدعم التقديم حساب Pro أو Max أو Team أو Enterprise مع الدور المؤهل، واتصال GitHub يمكنه الدفع إلى المستودع. تحقق من الدور المعروض داخل حسابك؛ هذه المسودة لا تثبت صلاحياته. [الأهلية](https://claude.com/docs/directory/publish).
2. افتح [بوابة الدليل](https://claude.ai/directory/manage)، واختر **Submit new → Plugin bundle**. أدخل رابط GitHub الحقيقي. اترك Plugin path فارغاً للحزمة الموجودة في الجذر، وحدد الفرع أو الوسم المتحقق منه؛ تركه فارغاً يتبع الفرع الافتراضي.
3. اختر **Validate**، وأصلح الأخطاء التي تمنع التقديم في المستودع ثم أعد الفحص. لا تعتبر مرور الفحص قبولاً. راجع الاسم والوصف وREADME والرخصة كما تستوردها صفحة Listing details.
4. في Data handling، اشرح المعالجة الفعلية: يمرر Claude مادة السيناريو المحددة إلى برنامج Node المحلي. الأدوات لا تخزن النص ولا تسجل محتواه ولا ترسل بيانات إلى خدمات أخرى أو تصل إلى الحسابات. قد يتضمن النص أسماء شخصية اختارها الكاتب؛ لا تنفِ احتمال معالجة بيانات شخصية. يحتفظ Claude بالمحادثة ونتائج الأدوات وفق إعدادات الحساب وسياسات Anthropic. حفظ ملف محلي جديد عمل ينفذه المضيف عند طلب الكاتب، وليس تخزيناً في خادم ريشة.
5. تحقق من بريد التواصل، وراجع إقرارات الشروط والسياسات والمعلومات القانونية، ثم أكمل Review and submit. الإقرار للناشر؛ لا تحل هذه المسودة محله. اختر طريقة متابعة الإصدارات مع فهم أثرها، ولا تفعّل النشر التلقائي من دون قرار مقصود.
6. تابع النتيجة، وعالج أي طلب مراجعة. النسخة التي تمر بالفحوص لا تصبح حية تلقائياً في جميع الحالات؛ نفّذ إجراء **Publish** المعروض وتحقق من ظهور النسخة المنشورة فعلياً قبل وصفها بأنها متاحة في الدليل. [دليل التقديم والنشر](https://claude.com/docs/plugins/submit).

## المحادثة العادية وCowork

يمكن إضافة Marketplace أو ZIP إلى حساب Claude من واجهة Plugins، لكن المكونات تختلف بحسب السطح. الخادم المحلي يعمل في Claude Code، ويُحمّل في جلسة Cowork تعمل على الكمبيوتر، ويُتجاهل في المحادثة العادية. يحتاج استخدام أدوات ريشة داخل المحادثة خادم MCP عاماً عبر HTTPS؛ إذا قدمنا خادماً بعيداً لاحقاً، يُقدّم هو أيضاً كـMCP connector مستقل إلى جانب حزمة الإضافة. [دعم المنصات](https://claude.com/docs/plugins/platform-support).

اختبار Cowork الفعلي، وتشغيل Node في بيئته، وتقديم الدليل وقرار Anthropic لم تُثبت بعد. رابط GitHub العام وحالة الاختبارات يُحدّثان بدليل التحقق عند اكتمالهما. لا توجد نسخة Chat remote connector في هذه الحزمة.
